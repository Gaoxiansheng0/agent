# Family Shelf 开发计划（v0.1）

> 工作名称：**Family Shelf**（上线前需做商标检索，可能更名）
> 发布主体：PearlWren（可选，落地页建议用 `familyshelf.pearlwren.com`）
> 目标市场：美国，英文产品与英文内容
> 商业模式：家庭订阅制（一个订阅覆盖全家所有成员）
> 文档日期：2026-10-22
> 前提假设：一人兼职开发，每周投入约 12–15 小时

---

## 0. 一页摘要

| 项目 | 内容 |
|---|---|
| 一句话定位 | 扫一瓶护肤品，立刻知道它适不适合你家**每一个人**（孩子、青少年、孕期、成人敏感肌……） |
| 核心差异化 | **以人为中心、多成员**的判断：一次扫描，按成员分别给出结论。现有产品要么按产品打一个统一分（如 Yuka），要么只针对单个用户做个性化（如 SkinSort、Glo） |
| 首个获客切入点 | 8–17 岁孩子的家长（"Sephora 小孩"现象） |
| 后续切入点 | 0–3 岁婴幼儿家长 → 孕期/哺乳期 → 成人档案（只作为家庭成员档案支持，不单独主打） |
| 收入目标 | 年流水约 4 万美元 ≈ **约 1000 个付费家庭 × $39.99/年** |
| 总周期 | 验证 3 周 → 构建 13 周 → 上线增长 6 个月；**每个阶段都设有止损线** |
| 最大风险 | 使用频率不足 / Yuka 或 SkinSort 跟进做家庭档案 / 判断失误的责任 / 成分数据过时 |

## 1. 产品定义

### 1.1 目标用户（注册的只能是 18 岁以上的家长）

| 角色 | 是否注册 | 说明 |
|---|---|---|
| 主账号持有人（家长，18+） | ✅ | 唯一的付费方和操作者 |
| 家庭成员档案（孩子、配偶、自己） | ❌ 不注册 | 只是主账号下的一张"档案卡"，不需要邮箱，也不需要真实姓名 |
| 13–17 岁青少年自己使用 | ❌ v1 不支持 | 避开德州等州的应用商店法和相关未成年人规则 |

### 1.2 核心使用场景（按优先级）
1. **购买前**：孩子在 Sephora 或 Ulta 想买新产品，家长拍一下，当场决定买不买。
2. **清点现有产品**：第一次使用时，把家里浴室里的产品全部扫一遍，生成"家庭产品架报告"。
3. **流程体检**：检查某个成员早晚的护肤流程，有没有重复的活性成分、有没有冲突、缺不缺防晒。
4. **人生阶段变化**：怀孕、宝宝出生、孩子进入青春期时，把全家产品重新检查一遍。

### 1.3 判断的输出口径（法律和信任的关键）
- 每个"产品 × 成员"的结论只分四档：
  - ✅ **Good fit**：适合
  - 🟡 **Use with care**：需留意，比如可能刺激、不宜叠加
  - 🟠 **Not recommended for this age/stage**：不建议该年龄或该阶段使用
  - 🔵 **Ask your doctor**：建议咨询医生，比如孕期涉及视黄醇类
- **不使用**"toxic / safe / dangerous"这类恐慌式或绝对化词汇。
- 每条警示都必须附上**依据来源**：机构指南或文献。
- 每个结果页底部固定显示：*Informational only. Not medical advice.*（仅供参考，不构成医疗建议）

## 2. 功能范围

### 2.1 MVP（v1.0）必须有

| 模块 | 功能 | 备注 |
|---|---|---|
| 引导流程 | 创建家庭 → 添加 1–6 个成员（昵称、出生年份或年龄段、可选的人生阶段和皮肤关注点）→ 第一次扫描 → 付费墙 | 参考 Cal AI 的多步引导，靠"用户投入感"提升转化 |
| 扫描 | ① 扫条形码查数据库 ② 拍成分表，用 AI 识别文字 ③ 手动搜索 | 条形码查不到时，自动切换到拍成分表 |
| 成分标准化 | 识别出的成分统一成国际通用的 INCI 名称，再归入成分组 | 见第 4 节 |
| 按成员给结论 | 一张卡片显示每个成员的四档结论和原因 | 核心卖点 |
| 成分解释 | 每个成分是做什么用的、为什么对某个成员需要留意 | 解释文字由规则生成，AI 只负责改写语句 |
| 家庭产品架 | 已扫产品列表，可标记"谁在用" | |
| 流程体检 | 为每个成员组合早晚流程，检测重复活性成分、冲突、缺防晒 | |
| 订阅 | 免费版 + Family Pro；3 天或 7 天试用 | 见第 7 节 |
| 隐私 | 成员档案和健康标记**只存在手机本地** | 见第 6 节 |

### 2.2 v1.x（上线后 1–3 个月）
- 每月花费统计（手动输入价格或读取条形码价格）。
- 开封后保质期提醒（例如 12 个月）。
- 同类替代建议：只推荐"对该成员更合适"的同类产品。**联盟链接是否接入，见第 7.3 节的利益冲突决策。**
- 分享卡片：把"某个产品对孩子不合适"的结论生成图片，发给另一位家长。这也是自然传播的入口。

### 2.3 v2（3–6 个月后，视数据决定）
- 婴幼儿规则包（0–3 岁），规则更保守。
- 孕期和哺乳期规则包。
- 成人关注点规则包：易长痘、敏感肌、真菌性痘痘等。
- 多设备同步：需要端到端加密，或者明确告知用户并取得同意（会触发健康数据合规）。

### 2.4 明确不做（Won't）
- ❌ 扫人脸、皮肤分析、AR 试妆（会触发伊利诺伊州生物识别法 BIPA）
- ❌ 给人或脸打分
- ❌ 疾病诊断或疗效宣称
- ❌ 青少年独立账号
- ❌ 自营化妆品电商
- ❌ 食品扫描（避免和 Yuka 的主战场正面竞争）

## 3. 用户流程（关键页面）

```
[启动] → [价值主张 3 屏] → [家庭设置：添加成员]
      → [成员详情：年龄段 / 人生阶段 / 关注点（可跳过）]
      → [立即扫第一件产品（强引导）]
      → [按成员显示的结果卡（Aha 时刻）]
      → [付费墙：解锁无限扫描、全部成员、流程体检]
      → [首页：家庭产品架 + 扫描按钮]
```

**Aha 时刻的设计原则**：首次扫描必须在 60 秒内出结果，而且至少有一个成员得到非 ✅ 的结论（如果确实有的话），让用户直观看到"同一瓶产品，对不同家人结论不同"。

## 4. 规则引擎设计（核心资产）

### 4.1 原则
1. **安全判断由确定性规则产生，不由大模型临场生成。**大模型只做两件事：从照片中识别成分表文字，以及在规则输出的范围内改写解释语句。这是控制责任风险的底线。
2. 每条规则都有：适用条件、严重级别、文案模板、依据来源、最后审核日期、审核人。
3. **默认保守**：证据不足时，给"Ask your doctor"或"Use with care"，不给 ✅。

### 4.2 数据结构

```yaml
IngredientGroup:          # 成分组
  id: retinoids
  members: [retinol, retinyl palmitate, retinal, adapalene*, ...]   # *处方/OTC 另行标注
  functions: [anti-aging, acne]

Rule:
  id: R-RET-AGE-01
  group: retinoids
  applies_to:
    age_band: [8-12]          # 或 life_stage: [pregnancy, breastfeeding]
    concern: null
  severity: not_recommended   # good | care | not_recommended | ask_doctor
  message_key: retinoid_young_skin
  sources:
    - org: AAD
      ref: "<指南标题 + URL>"
  reviewed_by: "<皮肤科医生姓名/执照州>"
  reviewed_at: 2027-01-xx

DuplicateRule:            # 跨产品叠加
  group: exfoliating_acids    # AHA + BHA + PHA
  threshold_products: 2
  severity: care
```

### 4.3 v1 规则覆盖范围（先求够用，不求全）
- **年龄段**：0–3 / 4–7 / 8–12 / 13–17 / 18+（v1 只启用 8–12、13–17、18+ 三档；0–7 岁档案显示"暂不支持，敬请期待"）
- **首批成分组**（约 20–30 组，覆盖绝大多数需要警示的情况；具体分组以文献整理结果为准）：
  - 视黄醇类、果酸（AHA）、水杨酸（BHA）、多羟基酸（PHA）、过氧化苯甲酰、壬二酸、高浓度维 C、香精/香料、精油类、常见致敏防腐剂、致粉刺成分（仅对"易长痘"关注点生效）、化学防晒剂、物理防晒剂（作为正面项）、对苯二酚等
- **流程规则**：重复的去角质成分、视黄醇和酸类叠加、白天流程缺防晒、步骤过多（例如 > 5 步时给出简化建议）

### 4.4 依据来源（优先级从高到低）
1. 专业机构的公开指南：美国皮肤科学会（AAD）、美国儿科学会（AAP）、美国妇产科医师学会（ACOG，孕期包使用）
2. 同行评审文献，例如西北大学 2025 年发表于《Pediatrics》的青少年护肤流程研究
3. 欧盟官方化妆品成分库 CosIng（用于 INCI 标准名和成分功能）
4. **v1 上线前：付费请一位美国执业皮肤科医生审核整套规则**，作为可对外宣传的信任背书

### 4.5 成分标准化流程
```
原始文本（OCR 或数据库）
 → 清洗（大小写、括号、"may contain"、百分比）
 → 别名映射（同义词表，例如 "Vitamin A" → retinol 组）
 → INCI 标准名
 → 成分组
 → 规则匹配
```
- 映射不到的成分记录为 `unknown`，**不影响结论**，但会进入人工复核队列。
- 每周看一次 `unknown` 的出现频率，补充别名表。

## 5. 技术方案

### 5.1 技术栈（适合一人开发，以速度优先）

| 层 | 选型 | 理由 |
|---|---|---|
| 客户端 | **Expo（React Native）+ TypeScript** | 一套代码同时出 iOS 和 Android；先上 iOS |
| 本地存储 | expo-sqlite | 成员档案和健康标记只存本地 |
| 条形码 | expo-camera 自带条码扫描 | |
| 产品库 | Open Beauty Facts 开放数据（导入自己的数据库）+ 自建补录 | 开放数据在美国市场的覆盖率需要验证，见风险表 |
| 成分表识别 | 视觉大模型 API（服务端代理），输出结构化 JSON | **只上传产品照片，不上传任何成员信息** |
| 后端 | Supabase（Postgres + Edge Functions）或 Cloudflare Workers + D1 | 只存产品、成分、规则这类**不涉及个人的公共数据** |
| 规则执行 | **在客户端本地运行**（规则包随版本下发，支持热更新） | 健康标记不必离开手机 |
| 订阅 | RevenueCat（订阅状态）+ Superwall（付费墙实验） | Cal AI 的付费墙实验也是在 Superwall 上做的 |
| 数据分析 | PostHog（**不上报任何成员属性或健康标记**） | 只上报事件和匿名计数 |
| 错误监控 | Sentry | |
| 落地页 | Astro 或 Next.js 静态站，部署在 Vercel 或 Cloudflare Pages | 同时承载第 8 节的 SEO 页面 |

### 5.2 架构示意

```
┌────────────── iPhone ──────────────┐
│ 成员档案 / 健康标记（本地 SQLite）  │
│ 规则包（本地，版本化）              │
│ 规则引擎（本地计算结论）            │
└──────┬──────────────────────┬──────┘
       │ 只发送：条形码 / 产品照片 │ 订阅状态
       ▼                         ▼
┌─────────── 后端（公共数据）────────┐   ┌──────────┐
│ 产品库 / 成分库 / 别名表 / 规则包    │   │RevenueCat│
│ OCR 代理 → 视觉大模型 → 结构化成分   │   └──────────┘
└────────────────────────────────────┘
```

### 5.3 核心数据表（服务端，均不含个人信息）
- `products(id, barcode, brand, name, category, ingredients_raw, ingredients_inci[], source, updated_at, verified)`
- `ingredients(inci, synonyms[], groups[], functions[])`
- `rules(id, group, applies_to, severity, message_key, sources, reviewed_at)`
- `rule_packs(version, published_at, changelog)`
- `unknown_tokens(token, count, first_seen)`：复核队列

### 5.4 成本估算（月度，上线初期；我的估算，置信度：中低）
- 视觉模型识别：按每次几美分估算，1000 个活跃家庭每月约 $30–150
- Supabase 或 Workers：$0–25
- RevenueCat：在一定收入门槛内免费（以官网最新条款为准）
- 苹果开发者账号：$99/年
- 合计：上线初期每月约 $50–200

## 6. 合规与风险控制清单

> 以下是产品层面的设计原则，**不是法律意见**。上线前预留预算，请美国律师做一次审阅。

| 主题 | 风险 | 设计对策 | 时间点 |
|---|---|---|---|
| 儿童隐私（COPPA） | 产品被认定为面向儿童，或收集了儿童的个人信息 | 只允许 18+ 注册；儿童档案只有昵称和年龄段，不收集姓名、照片、声音；不上架儿童类目 | MVP |
| 州应用商店问责法（德州已生效，犹他、路易斯安那、阿拉巴马已立法） | 未成年人下载或内购需家长同意 | 不允许未成年人自己注册；年龄分级如实填写；跟踪应用商店年龄信号接口的要求 | MVP + 持续跟踪 |
| 健康数据（华盛顿州《My Health My Data Act》及其他州类似立法） | 孕期、皮肤疾病属于消费者健康数据，允许个人直接起诉 | **健康标记只存本地，不上传、不进分析、不进广告归因**；单独的健康数据隐私政策；如果以后做云同步，必须先取得明确同意 | MVP |
| 生物识别（伊利诺伊州 BIPA） | 采集面部几何特征 | **不做任何人脸功能** | 永久 |
| 医疗宣称 / 医疗器械 | 被认定为诊断工具 | 只做成分信息判断；不出现"治疗、诊断、治愈"等词；固定免责声明 | MVP |
| 品牌方投诉或诽谤风险 | 负面结论引发品牌法律行动 | 每条结论都附依据来源；用"适配度"措辞，而不是"有害"；提供"报错/申诉"入口 | MVP |
| 网红营销（FTC 披露规则） | 合作内容未标注广告 | 合同要求带 #ad 等披露标识 | 增长期 |
| 数据准确性 | 配方调整后成分表过时 | 产品页显示数据日期；用户可报错；拍照识别的结果优先于数据库 | MVP |
| 商标 | 名称冲突 | 上线前检索美国商标局（USPTO）数据库，准备 2–3 个备选名 | 验证期 |
| 主体与收款 | 个人开发者账号会公开显示真名 | 决定用个人还是公司主体；完成苹果税务资料（W-8BEN 等） | 开发期 |

## 7. 商业模式

### 7.1 定价（初版，上线后用付费墙实验调整）

| 档位 | 价格 | 包含 |
|---|---|---|
| Free | $0 | 每月 5 次扫描、2 个成员、只看结论不看原因 |
| **Family Pro（年付，主推）** | **$39.99/年** | 无限扫描、6 个成员、原因与依据、流程体检、花费统计 |
| Family Pro（月付） | $6.99/月 | 同上（主要用于衬托年付更划算） |
| 创始会员（验证期预售） | $19.99 首年 | 同 Pro，锁定首年价格 |

- 试用：先测 3 天和 7 天两个版本，由数据决定。
- 付费墙实验的顺序：① 价格锚点 ② 试用时长 ③ 付费墙出现在第一次扫描之前还是之后 ④ 文案。

### 7.2 收入测算（我的估算）
- 目标年流水约 $40,000；苹果小企业计划抽成 15% 后约 $34,000，再扣除 API 和投放成本。
- 需要约 **1000 个年付家庭**。
- 倒推漏斗（假设值，上线后用真实数据替换）：
  - 下载 → 开始试用：15–25%
  - 试用 → 付费：30–45%
  - 下载 → 付费：约 5–10%
  - **需要约 1–2 万次下载/年**

### 7.3 关键决策：要不要接联盟佣金？
- 赞成：多一份收入，替代品推荐可以直接变现。
- 反对：Yuka 的核心信任资产就是"不收品牌的钱、不做联盟"。一旦接了佣金，结论的可信度会受质疑。
- **建议**：v1 不接；如果以后接，必须明确披露，并保证推荐排序只由规则决定。

## 8. 获客计划

### 8.1 渠道优先级
1. **短视频（TikTok / Instagram Reels / YouTube Shorts），不露脸**：录屏加拍产品。
   - 钩子 A："I scanned my 11-year-old's Sephora haul"（扫了我 11 岁孩子从 Sephora 买的东西）
   - 钩子 B："One scan, every person in my family"（一次扫描，全家每个人都有结论）
   - 钩子 C（v2 之后）："I scanned every baby product in our nursery"（扫了婴儿房里所有宝宝用品）
2. **程序化 SEO 页面**：用规则库自动生成"Is [产品/成分] OK for a 10-year-old?"之类的页面。这是一人公司成本最低的长期渠道。必须遵守措辞规范，并附依据来源。
3. **家长社群**：Facebook 家长群、Reddit 相关板块（例如 r/Parenting、r/SkincareAddiction；需遵守各板块的推广规则）。
4. **专业人士合作**：皮肤科医生、美容师、学校护士——提供免费账号和可分享的"家长指南"PDF。
5. **小网红按月固定付费**（Cal AI 模式的缩小版）：从 5–10 个家长博主开始，按播放效果续约。

### 8.2 内容生产节奏（兼职可行）
- 每周 5 条短视频（批量拍摄、批量剪辑，约 4 小时）。
- 每周新增 20–50 个 SEO 页面（规则库自动生成，人工抽检）。

## 9. 里程碑与时间表

> 按每周 12–15 小时估算。所有"止损线"都是硬性规则，到点只看数据做决定。

### 阶段 0：需求验证（第 1–3 周）· 不写 App 代码

| 任务 | 产出 |
|---|---|
| 商标初检，确定工作名称 | 2–3 个备选名 |
| 落地页（含 3 个钩子版本）+ 预售支付 | `familyshelf.pearlwren.com` |

**止损线 G0**：$600 总预算内，3 个钩子合计**创始会员预售少于 30 单** → 停止这个方向。
**通过后**：选出获客成本最低的钩子作为主打。

### 阶段 1：数据与规则（第 4–6 周）

| 任务 | 产出 |
|---|---|
| 导入 Open Beauty Facts 数据，测试美国热门品牌的条形码命中率 | 命中率报告（目标 ≥ 50%，否则主路径改为拍成分表） |
| 别名表与成分组 v1（20–30 组） | `ingredients`、`groups` 数据 |
| 规则 v1（8–12、13–17、18+ 三档 + 流程规则） | `rules` 数据 + 来源清单 |
| 成分表识别准确率测试（100 张真实标签照片） | 成分识别 F1 值（目标 ≥ 0.95，按成分计） |
| **聘请皮肤科医生审核规则** | 审核意见与修订记录 |

**止损线 G1**：识别准确率达不到 0.9，且两周内无法改进 → 推迟上线，转为"条形码优先 + 人工补录"模式。

### 阶段 2：MVP 开发（第 7–12 周）

| 周 | 内容 |
|---|---|
| 7 | 项目搭建、导航、本地数据库、家庭与成员管理 |
| 8 | 扫描（条形码 + 拍照）、OCR 代理、成分标准化 |
| 9 | 本地规则引擎、按成员结果卡、成分解释页 |
| 10 | 家庭产品架、流程体检 |
| 11 | 引导流程、RevenueCat + Superwall 付费墙、PostHog 事件埋点 |
| 12 | 隐私政策 / 服务条款 / 健康数据政策、App Store 隐私标签、性能与错误修复 |

### 阶段 3：内测（第 13–15 周）
- TestFlight 邀请创始会员（目标 50–100 人）。
- 跟踪以下指标：首次扫描完成率、每个家庭每周扫描次数、"报错"率、未识别成分 Top 50。
- 每周发一个版本，补充别名表和规则。

**止损线 G3**：内测期间**每个家庭每周平均扫描次数 < 1**，并且访谈确认"扫完一遍就不再打开" → 重新设计复用场景（购买前扫描、新产品提醒），否则不上线付费版。

### 阶段 4：上线（第 16 周）
- iOS 上架美国区（Android 根据第一个月数据再决定）。
- 上线首月：每周做一个付费墙实验。

### 阶段 5：增长与扩展（第 4–12 个月）

| 时间 | 重点 |
|---|---|
| 第 4–6 月 | 跑通单一钩子的获客；程序化 SEO 页面上线 500+ 个；v1.x 功能 |
| 第 6–9 月 | 婴幼儿规则包（另请医生审核）；测试钩子 C |
| 第 9–12 月 | 孕期规则包（只作为成员档案，不主打）；评估 Android；评估是否需要云同步 |

**止损线 G5（上线后第 6 个月）**：付费家庭少于 300，**或者**获客成本 > 首年收入 × 70% → 停止投放，只保留 SEO 和自然流量，把时间转向其他项目。

## 10. 核心指标（数据看板）

| 层级 | 指标 | 初期目标（假设值） |
|---|---|---|
| 激活 | 下载后 24 小时内完成首次扫描 | ≥ 60% |
| 激活 | 添加 ≥ 2 个成员的比例 | ≥ 50% |
| 复用 | 每个家庭每周扫描次数 | ≥ 1.5 |
| 转化 | 下载 → 开始试用 | ≥ 15% |
| 转化 | 试用 → 付费 | ≥ 30% |
| 留存 | 年付用户的次年续费率 | ≥ 40%（首年结束时验证） |
| 质量 | 结论被"报错"的比例 | ≤ 2% |
| 质量 | 未识别成分占比 | ≤ 3% |
| 获客 | 每个付费用户的获客成本 | ≤ $20 |

> 原则：分析系统**只记录事件和匿名计数**，不记录任何成员的年龄段、人生阶段或皮肤关注点。
